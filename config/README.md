# config

The default settings of the v1.0 filter generator. **Players: do not edit these files.** Make a
profile with only the files and values you change (`profiles/<name>/`), as the
[Customization Guide](../.docs/customization_guide.md) explains; this folder is updated with the
repository.

| File | Format | Contents |
|---|---|---|
| `band_rules_<category>.csv` | CSV, ASCII only, no BOM | Per-band rules: item × 9 bands; the rules are explained in [filtering_philosophy.md](../.docs/filtering_philosophy.md) |
| `band_rules_gems.csv` | CSV, ASCII only | Gems per band and gem level (generated: `engine/rulegen/build_gem_rules.py`) |
| `band_rules_league.csv` | CSV, ASCII only | League items (essences, catalysts, liquids, Expedition, splinters, keys, bones, omens) by exact name (generated: `engine/rulegen/build_league_rules.py`) |
| `band_rules_socketables.csv` | CSV, ASCII only | Socketables (runes, soul cores, idols, named runes) by exact name (generated: `engine/rulegen/build_socketable_rules.py`) |
| `band_rules_flasks.csv` | CSV, ASCII only | Life/Mana Flasks per base (only the best of each band), with the Charm class rule (rare only) (generated: `engine/rulegen/build_flask_rules.py`) |
| `band_rules_jewels_quest.csv` | CSV, ASCII only | Jewels by rarity, the Time-Lost variant separately; the Quest Items class rule (hand-written) |
| `band_rules_unique.csv` | CSV, ASCII only | The Unique+ rule: every class, every band; the first section of the filter |
| `band_rules_gold.csv` | CSV, ASCII only | Gold per level; here a cell is the minimum `StackSize` (a different cell meaning), and the `sound`/`border` columns are the exception |
| `band_rules_catch_all.csv` | CSV, ASCII only | The catch-all: the last section of the filter, it only catches unmatched items |
| `band_rules_map_items.csv` | CSV, ASCII only | Map items: Waystones per tier, the rest per class (generated: `engine/rulegen/build_map_rules.py`) |
| `overrides.csv` | CSV, ASCII only | Manual fixes of single rows (see below); empty by default |
| `base_exceptions.csv` | CSV, ASCII only | The implicit exception list: implicit id (without the final digit), class, label, effect |
| `jewellery.csv` | CSV, ASCII only | Border and icon colour of rings and amulets by implicit; `*` = class rule (belts) |
| `structure.toml` | TOML | Structural settings: RePoE and catalog, output, bands, importance scale, sound families, colour categories, attribute colours, icon shapes, section order (`[output] sections`), background (`[style] default_background`, black on every label). Values commented `DEFAULT` were chosen but not yet confirmed by play-testing. |

**Generated or hand-written:** do not edit a *generated* CSV by hand. Its source is the rule
script (`engine/rulegen/`, regenerated by `regen_all.py`), and it is overwritten on every update.
A manual fix of a generated item goes into `overrides.csv`. The other CSVs are hand-written: the
file itself is the source.

**The `overrides.csv` format:** columns `section` (a section name from `structure.toml` `[output]
sections`), the key (`name`, `match`, `item_class`, `rarity`, `gem_level`, `waystone_tier`, as in
the target row; empty where the target row is empty too), then the columns that can be changed
(`family`, `category`, the bands) and `note` (the reason). An empty cell keeps the generated value.
Every row must hit exactly one target row, otherwise `engine.config` reports an error. A new item
is not added by an override but by the rule script or a hand-written CSV. Example: Omen of Light at
level 5 with a light beam in the 86-99 band:
```
league,Omen of Light,exact,,,,,,,,,,,,,,,5b,example
```

**Why two formats:** a structural setting is nested name–value data (TOML: Python reads it
without extra packages, and it allows comments); a band rule is a two-dimensional table (CSV:
editable in Excel, comparable line by line). Neither needs an external package.

**Why ASCII only in the CSVs:** on Windows, Excel does not open a UTF-8 CSV without a BOM as
UTF-8, so non-ASCII characters (e.g. `★`) get corrupted.
